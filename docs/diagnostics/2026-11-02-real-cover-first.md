现场只读检查发现，主窗口及桌面歌词的当前封面均已解码为 1024×1024 图片。主窗口所用图片为 389950 bytes、`image/png`；SHA256 为 `b79f3e4cf564a36f77679a41e9e3a20116f79445b931147626e3517e8965a9d7`。与本地默认图的 666812 bytes、SHA256 `275cda5c31ea0d98c1b6046ae2593b1abe6ef088dc04fa5bda8323bbc1ef40d2` 不同。因此本轮没有现场复现用户报告的间歇性真实封面缺失，不能将其统一归因为某个新的 CDN 故障。

源码确认了可独立复现的问题：`atom://get-image` 在实际取图失败时返回 HTTP 200 和默认图，Renderer 无法区别真实封面与替代图；普通封面卡片没有使用现有的有限 CDN 代理恢复路径；桌面歌词忽略空封面更新，可能保留上一首图片。旧播放器快照中的默认图还可能挡住实际歌曲详情的补取。

## 最终行为

1. 有真实封面 URL 时，先加载该图片。
2. 网易云图片失败时，进行一次同资源代理请求。主进程沿用现有的 CDN 候选、每个候选 3.5 秒取消信号、8 MiB 上限和响应流清理策略，不增加重试次数，不删除鉴权参数。
3. 代理取图确实失败时返回 502 和 `Cache-Control: no-store`，禁止把失败包装成成功图片。
4. Renderer 收到失败后才请求本地默认图，明确记录 `data-vutron-cover-state=fallback`。默认图本身失败时终止，不循环请求。
5. 缺少真实封面 URL 时，播放器先完成现有五次歌曲详情补取（原间隔 2/5/10/20/40 秒）。仍然没有 URL，才发出默认图信号。切歌清除旧封面；旧异步任务仍受曲目版本检查约束。
6. 新的真实封面 URL 到达后重置该图片的恢复阶段，正常替换默认图。普通封面卡片、底部播放器、经典播放器、桌面歌词共用图片恢复逻辑。
7. 导出诊断增加当前最终默认图数量，原有加载统计和导出入口保留。未新增定时图片重试、全局图片缓存或 URL 日志。

对缺失元数据的等待与图片请求的恢复分别计数，不把默认图当成歌曲元数据中的有效封面。没有向上游补造图片，也不能保证已经删除或被限制的真实图片一定能恢复。

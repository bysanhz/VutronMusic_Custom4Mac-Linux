# 2026-11-03 音源身份错配：落日微风播放成雨爱

## 实际现场与根因

起始源码 `8541c295fe6e5ab19494c8659aae711333348934`，系统安装版的代码仍为 `672ef63`。本轮开始时工作区干净，运行中的应用未为取证重启或切歌。

通过当前应用的只读本机播放器接口取得现场，另外读取上游媒体文件标签和只读 SQLite 缓存记录：

| 项目                                  | 观测                                         |
| ------------------------------------- | -------------------------------------------- |
| 界面曲目                              | 落日微风 / 张德伊玲，NetEase ID `1900247879` |
| 曲库标称时长                          | 188.672 秒                                   |
| 实际选择来源                          | Bodian，音频主机 `bd-er.kuwo.cn`             |
| 媒体实际时长                          | 259.5 秒                                     |
| 实际文件标签                          | TITLE=雨爱，ARTIST=张德伊玲，ALBUM=雨爱      |
| 当前播放是否读取磁盘缓存              | false                                        |
| trackLoadRevision / mediaLoadRevision | 8 / 8                                        |
| 当前源重试 / 停滞恢复次数             | 0 / 0                                        |

该案例的直接错误发生在备用源候选选择，证据不支持将其归因于一次旧恢复请求覆盖新歌。官方 hires URL 请求此前失败并返回 500 是进入备用路径的触发条件；本轮未认定 500 的原因是版权或会员权限。

`@unblockneteasemusic/server@0.28.0` 的 `src/provider/bodian.js` 搜索酷我曲库，随后调用共享 `src/provider/select.js`。共享选择器只在前五项中寻找时长相差五秒以内的项目，找不到就 `return list[0]`，未验证曲名、艺人或版本。

用实际曲目与相同搜索参数重新请求，首项是酷我 ID `463949837` 的“雨爱 / 张德伊玲”，时长 259 秒。列表中的同名“落日微风”分别属于其他艺人，不能替代目标歌曲。原选择器对这份响应确实选择“雨爱”；改后的选择器拒绝全部不符项目。媒体实际标签、时长与旧选择结果相吻合。

这是已经形成闭环的错播证据，不是仅凭标题不同作出的推测。现场与脱敏缓存结果见 [observed.json](artifacts/2026-11-03-audio-identity/observed.json)，真实搜索响应的候选元数据见 [测试夹具](../../tests/fixtures/audio-identity/luori-kuwo.json)。没有提交完整音频、Cookie、私人队列、鉴权 URL 或原始账号配置。

## 缓存为何让问题持续

缓存 worker 的旧逻辑只确认“这是不是音频”，随后把外部响应关联到原始歌曲 ID，并写入目标曲目的封面等标签。`cacheATrack` 又重新取得原歌曲信息，未传递实际备用来源，因此数据库可能仍标记 source=netease。

只读检查确认 ID `1900247879` 已有 cache=true 的磁盘记录，文件标签依旧是“雨爱”，时长 259.5 秒。虽然本次现场先使用远程 Bodian URL，后续仍可能从这份错误缓存继续错播。源选择错误是首次错播根因，缓存是持久化放大路径。

## 修改

- `src/shared/audioIdentity.ts`：统一核对曲名、艺人名单和已知时长；允许大小写、空格、全半角和标点差异，保留 Live、伴奏、Remix、Cover 等名称文字。检查完整候选列表，不再无条件退回首项。已知时长偏差超过五秒则拒绝；部分来源没有时长时，仍必须有相符曲名和艺人。
- `src/main/utils/unblockMatcher.ts`：在 UNM provider 捕获选择器之前，替换该依赖自身缓存中的选择函数；不改 node_modules 文件，不安装全局模块加载钩子，也不增加依赖。传入应用已取得的规范歌曲信息，避免再次按 ID 从另一路 API 获取元数据。按来源隔离验证结果，近期身份输入最多保留 32 组。
- 当前依赖的视频搜索路径丢弃候选元数据，无法通过同一身份核对，因此这类不可核验的搜索回退会被拒绝。配置项保留，不能确认身份时尝试其他来源或按原有有限失败路径结束；这可能减少可播结果，避免把任意搜索首项当作本曲。直接按原 NetEase ID 请求的 pyncmd 单独标记为 direct-id-source，不冒称候选元数据已验证。
- 依赖没有公开的候选注入接口，适配绑定当前实际 `0.28.0` 模块结构。若结构或加载顺序变化，按不可用处理，不回退到不安全选择；真实依赖模块测试负责暴露这种漂移。
- `src/main/workers/cacheTrack.ts`：下载后、改标签和写文件前读取真实媒体元数据，拒绝可观测的曲名、艺人、时长冲突。
- `src/main/utils/cachedAudioIdentity.ts` 与 `src/main/index.ts`：在线旧缓存首次被请求时核对真实文件；不符时绕过这份缓存并重新解析音源。保留用户文件，不批量删除缓存。
- `src/renderer/store/player.ts` 与 `src/main/IPCs.ts`：在线缓存不绕过主进程核对；缓存任务传递实际音源来源，避免把备用来源再标成 NetEase。普通本地文件仍按原路径播放。无可用音源时清除旧媒体源，暂停恢复失败时保持暂停，不自动切到下一首开始播放；主动播放中的自动切歌路径保留。
- 音源诊断增加 candidate-verified / candidate-rejected / identity-rejected 等阶段；继续使用有界、脱敏的既有记录。没有增加重试预算，没有修改心动模式排序、听歌计时、账本或历史上报记录。

## 验证与限制

新测试使用真实依赖模块和受控网络响应复现旧选错行为，再检查修复拒绝错误首项、接受后续正确项；另覆盖同名不同艺人、相近时长但不同歌名、版本文字、未知身份、旧缓存文件内容、缓存写入前拒绝，以及并行来源不能借用其他来源的验证结果。

修复适配器还对实际在线 Bodian 搜索重新运行：目标曲目没有相符候选时返回不可用，不再取得“雨爱”的播放 URL。真实磁盘错误缓存被新校验识别为 title_mismatch，原文件仍在。

元数据核对不是音频指纹鉴定：同名、同艺人、近似时长且标签被错误改写的另一份录音，仍可能无法区分。当前证据证明该错播与错误缓存路径受到拦截。安装后又取得了原 ID 对应的 pyncmd 音源，新文件标签与 188.672 秒时长一致；没有进行音频指纹比对，不将其扩大为所有平台、所有来源都已穷尽验证。

本轮仅复现并修复音源身份问题；README 截图时记录的本地歌词 null 问题和历史数 GiB 内存异常，不在这里声称已解决。
